Danh Mục 3 Điểm Kiểm Tra Khuyến Nghị (Kèm Trích Dẫn Chuẩn):

Cloud Run tự động tiêm biến PORT (mặc định 8080) vào container. Ứng dụng phải đọc biến này qua process.env.PORT || 8080 thay vì gắn cứng cổng 3000.

📖 Nguồn tài liệu: Google Cloud Run: Configuring Container Services

Nếu bind vào localhost, chỉ nội bộ container mới kết nối được. Router ngoài của Cloud Run không thể gửi request kiểm tra sức khỏe. Container bắt buộc phải lắng nghe trên 0.0.0.0.

📖 Nguồn tài liệu: Cloud Run Container Contract - Ingress & Port Listening

Chỉ thị EXPOSE trong Dockerfile chỉ mang tính tài liệu hóa (metadata). Đổi EXPOSE 8080 sẽ không có tác dụng nếu mã nguồn server.js vẫn đang lắng nghe ở cổng khác hoặc bind localhost!

📖 Nguồn tài liệu: Docker Documentation - EXPOSE Specification

Cấu hình Cổng Động từ Biến Môi Trường (PORT)

Cloud Run truyền cổng qua biến môi trường PORT. Ta cần đổi khai báo cổng cố định thành const PORT = process.env.PORT || 8080; để ứng dụng thích ứng với môi trường Cloud Run lẫn chạy thử local.

📖 Dẫn chứng: Cloud Run Docs: Configuring Container Port
BƯỚC 2 / 3

Lắng nghe trên Địa Chỉ Mạng Mở 0.0.0.0

Mặc định localhost chỉ nhận kết nối nội bộ. Cloud Run yêu cầu ứng dụng phải bind vào 0.0.0.0 để bộ điều hướng bên ngoài gửi được lưu lượng vào container.

📖 Dẫn chứng: Cloud Run Container Contract: Listening on 0.0.0.0
BƯỚC 3 / 3

Hiểu đúng Mối Quan Hệ Giữa Dockerfile và Mã Nguồn

Nếu Dockerfile có lệnh ENV PORT=8080, đó là giá trị dự phòng cục bộ khi test Docker local. Khi chạy trên Cloud Run thật, nền tảng luôn ghi đè giá trị này. Do đó mấu chốt kỹ thuật nằm ở việc mã nguồn server.js phải đọc giá trị này!

Khảo sát Dockerfile & Hướng dẫn Local Test:

Khi kiểm thử container cục bộ trước khi đẩy lên Cloud Run, bạn có thể chạy lệnh:

docker run -p 8080:8080 -e PORT=8080 my-image

Bạn cũng có thể chuyển sang để đối chiếu tài liệu độc lập.
